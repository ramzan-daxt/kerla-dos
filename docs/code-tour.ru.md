# Как разобраться в Kerla Doş

Цель этого разбора: самому проследить работу приложения, изменить небольшой участок и объяснить результат. Начинай с карточек и избранного. Книги и мозаика заметно сложнее, их можно разобрать позже.

## 1. Запусти проект и найди точку входа

```sh
npm ci
npm run dev
```

`app/layout.tsx` задаёт общий HTML и подключает стили. `app/page.tsx` отвечает за главную страницу. Директива `"use client"` позволяет использовать обработчики нажатий и React hooks. Она не означает, что браузерные API безопасно вызывать прямо при рендере: Next.js также предварительно создаёт HTML.

Поэтому `localStorage` читается после первого рендера, в эффекте внутри `useLearningProgress`. Первый HTML и первый браузерный рендер используют одинаковые значения по умолчанию.

## 2. Данные отдельно от интерфейса

Открой `app/types.ts`, затем `app/data/vocabulary.ts`.

`Word` описывает одно слово: стабильный `id`, чеченское написание, перевод, необязательные пути к изображению и аудио. `Category` объединяет слова. `LessonPosition` хранит категорию и номер карточки.

Компонент получает данные и строит интерфейс. Например, `categories.map(...)` превращает категории в кнопки, а `active.words[index]` выбирает карточку. `key` помогает React отличать соседние элементы списка. Для слов используются их идентификаторы, а не случайные значения.

Практика: найди уже существующее слово и проследи, откуда приходит его изображение. Не меняй чеченское написание наугад: словарь содержит согласованные исправления и отдельные правила орфографии.

## 3. Что происходит после нажатия на категорию

Найди `open` в `app/page.tsx`.

1. Останавливается прежнее аудио и сбрасываются таймеры анимации.
2. Выбирается категория через `setActive(cat)`.
3. Устанавливается индекс первой или сохранённой карточки.
4. Сбрасываются предыдущий ответ и состояние викторины.
5. React повторно вызывает компонент и показывает экран выбранной категории.

`useState` хранит то, что влияет на изображение интерфейса: текущую категорию, индекс, выбранный ответ, открытое окно настроек. Нельзя менять эти значения обычным присваиванием и ожидать обновления экрана; нужен setter.

В этом проекте экраны переключаются локальным состоянием, а не отдельными URL. Это упрощает прототип, но означает, что нельзя отправить ссылку прямо на определённую карточку. Возможное улучшение: отдельные маршруты или параметры URL.

## 4. Как устроены избранное и сохранение

Проследи цепочку:

```text
нажатие на сердце
  → toggleFavorite(key) в page.tsx
  → update("favorites", previous => ...)
  → новое состояние в useLearningProgress
  → повторный рендер
  → эффект сохраняет данные через writeProgress
```

Ключ вроде `animals:cat` различает слова из разных категорий. `includes` проверяет наличие слова, `filter` удаляет его, `[...previous, key]` добавляет без изменения старого массива.

Функциональное обновление получает актуальное предыдущее состояние. Внутри такого обновления не должно быть записи в хранилище или других побочных действий: React может повторно вызвать функцию. Сохранение вынесено в эффект.

`progress-storage.mjs` отдельно проверяет JSON, массивы, допустимые настройки и индекс карточки. Если хранилище заблокировано или заполнено, приложение продолжает работать в памяти. Флаг `loaded` не позволяет первым значениям по умолчанию затереть сохранённые настройки.

Практика: включи немецкий перевод, сохрани слово в избранное, перезагрузи страницу и проверь оба изменения. Затем прочитай соответствующий тест в `tests/progress-storage.test.mjs`.

## 5. useRef и useEffect на примере звука

`useRef` хранит значение между рендерами, но изменение `.current` само по себе не перерисовывает экран. Здесь это подходит для аудиоэлемента, таймеров и состояния жеста.

`audio-pool.mjs` переиспользует аудиоэлементы. Это уменьшает повторное создание объектов при переходе к соседним карточкам. Счётчик `audioRequest` помогает отличать текущую попытку воспроизведения от устаревшей: запоздалый отказ старой записи не должен запускать чужой голос поверх новой карточки.

`useEffect` связывает React с внешними системами: хранилищем, событиями клавиатуры, аудио. Возвращаемая функция очищает подписки и таймеры. Без очистки после повторного открытия экрана могли бы работать несколько обработчиков одновременно.

Важное ограничение: запасной синтез речи использует `ru-RU`. Это технический запасной вариант, а не корректная озвучка чеченского языка. На интервью можно самостоятельно назвать эту проблему и предложить заменить её проверенными записями.

## 6. Почему ответы викторины не перемешиваются при каждом рендере

В `quiz-options.mjs` функция получает слова, правильный ответ, число вариантов и номер раунда. Она создаёт новый массив, добавляет правильный ответ один раз и перемешивает копию.

Порядок воспроизводим для одного раунда. Поэтому открытие интерфейса или выбор ответа не переместит кнопки под пальцем. При следующем раунде порядок меняется. Это не криптографический генератор; для расположения учебных карточек он не нужен.

Практика: прочитай `tests/quiz-options.test.mjs`. Объясни, что проверяют отсутствие повторов, неизменность исходного массива и присутствие правильного ответа. Попробуй добавить проверку для двух слов и четырёх запрошенных вариантов.

## 7. Props и общий компонент окна

В `settings.tsx` компонент получает настройки через `value`, а изменения сообщает наверх через `onChange`. Это props: входные данные и функции, переданные родительским компонентом.

`components/modal.tsx` отвечает за общие действия окна: начальный фокус, Tab внутри окна, закрытие по Escape и возвращение фокуса на кнопку открытия. Содержимое передаётся как `children`. Благодаря этому настройки и другие окна используют одно поведение, сохраняя свои стили.

Практика: открой настройки только клавиатурой, пройди элементы через Tab, закрой Escape. Проверь, куда возвращается фокус.

## 8. Что пока стоит улучшить

- Разделить оставшийся большой `page.tsx` на экран категории, карточку и викторину.
- Убрать недоступные старые ветки чтения из `home-extras.tsx`, предварительно проверив связанные тесты.
- Пересмотреть зависимости старых эффектов. Предупреждение линтера иногда означает, что обработчик использует устаревшие значения.
- Добавить автоматические браузерные сценарии. Нынешние тесты не проверяют весь интерфейс.
- Сократить вес изображений и отделить рабочие версии от архивных вариантов.
- Заменить демонстрационные платежи и аудио перед реальным коммерческим выпуском.

## Как говорить о проекте на собеседовании

Удобный порядок: для кого приложение → один рабочий сценарий → как устроено состояние → одна техническая проблема → следующее улучшение.

Например, после собственного разбора можешь сказать:

> Das ist mein Lernprojekt mit React, Next.js und TypeScript. Es geht um das Lernen tschetschenischer Wörter mit Karten und kleinen Spielen. Die Kategorien und Wörter liegen getrennt von den Komponenten. Einstellungen und Fortschritt werden lokal im Browser gespeichert. Ich kann Ihnen am Beispiel der Favoriten zeigen, wie ein Klick den State verändert und wie die Daten gespeichert werden.

Не заучивай абзац, если пока не можешь показать эти места в коде. Лучше уверенно объяснить один сценарий, чем перечислить десять технологий.

Если спрашивают о помощи инструментов, можно прямо объяснить: код разрабатывался с помощью ИИ, а сейчас ты разбираешь решения, проверяешь поведение и учишься самостоятельно вносить изменения. Это не заменяет знания React, но даёт конкретную основу для обучения.
